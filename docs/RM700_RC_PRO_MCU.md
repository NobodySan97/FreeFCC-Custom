Разбор прошивки `V02.02.0803_rm700_dji_system.bin` (DJI RC Pro, умный пульт для
Mavic 3). Источник — сетевая шара `dji_firmware`, загружена пользователем
2026-07-25. Контейнер — обычный tar (`rm700.cfg.sig` первым элементом), три
модуля.

MCU-модуль `0600`: `auth_key=PRAK`, `enc_key` пустой → образ открытый.
`BUILD Oct 24 2023 21:15:44`, ядро GD32 (`gd32_drv_*`, `DJI V1 Protocol`,
`DJI HOST Protocol`). Reset vector `0x08010630` ⇒ загрузочная база
`0x08000000`.

## Таблица команд

`{u32 handler(thumb) | u8 cmd_id | u8 cmd_set | u16 fa | u16 fb | u8 x | u8 y}`.
У всех рабочих записей `fa=0x0100 fb=0xffff x=00 y=ff`; финальная запись —

## `06:72` / `06:74` / `06:84` — где rm700 в споре «поколений»

rm700 несёт **все три** ID одновременно. По потоку управления обработчиков
(строки `set/get stick value lock` в них не грузятся — логирование вынесено в
общий телеметрийный хелпер, поэтому это вывод из CFG, не string-proof):

- **`06:72`** `0x0801f888` — **сеттер**: `tbb`-таблица переходов по индексу
  `0…5` (`cmp r3,#5`), в каждой ветке пишет значения из входного payload
  (`ldr [r2]`→`str [r0,#0x14/#0x18]`, вызовы под-сеттеров `0x801f9f8`,
  `0x801fa1c`, `0x801fa2c`). Структурно — «записать шесть каналов».
- **`06:74`** `0x0801fa40` — **геттер**: читает состояние (`ldrb [r4]`),
  ветвится и через `0x8009d74` формирует ack с сохранёнными значениями из
  `r4+4`, `r4+8`. Структурно — «вернуть сохранённое».
- **`06:84`** `0x0801f1c0` — другое: читает одиночный статус-байт
  `[r4,#0x481]` и логирует; на stick-lock не похоже.

То есть по оси set/get **rm700 ложится на схему RC2** (`72`=set, `74`=get), а
не на схему RC Pro 2 / RM510 (`74`=set, `84`=get). Это ослабляет прежний тезис
«исключение — только RC2»: RC Pro группируется с RC2. Оговорка прежняя —
назначение доказано лишь структурно и требует live-теста (отправить `06:72`,
считать `06:74`). См. [[RC_MCU_DUML_COMMAND_MAP]].

Строка декодирования каналов присутствует и здесь:
`WARNING:A:%d E:%d T:%d R:%d WH1:%d WH2:%d c1:%d c2:%d fo:%d pho:%d rec:%d
f_m:%d c3:%d rc_m:%d pau:%d wheelmode %d` — подтверждает **четыре оси + два
колеса** (`WH1`, `WH2`) и камерные кнопки (focus/photo/rec) из собственной
прошивки rm700, без заимствования строки у других пультов.

## Метод и воспроизведение

1. `tar xf V02.02.0803_rm700_dji_system.bin` → три `.pro.fw.sig`.
2. `dji_imah_fwsig.py -u -f -i rm700_0600_*.pro.fw.sig -m rm700_0600` (PRAK,
   `enc_key` пустой) → `rm700_0600_0600.bin`.
3. База `0x08000000` (из reset vector), таблица найдена сканером записей
   rc520-формата; полный экстент — прогулкой по stride-12, пока `handler`
   попадает в диапазон образа.
4. Обработчики `72/74/84` — capstone Thumb, база `0x08000000`.

Ключи-инструменты в scratchpad: `mcu_scan_rc520fmt.py` (беззатравочный поиск
таблицы), `disasm_thumb.py` (`MCU_BASE=0x08000000`).
