# RC MCU (`rc331`, `rc520`): полная карта DUML-команд

Дата анализа: 2026-07-24.

Продолжение [`RC331_MCU_FIRMWARE.md`](RC331_MCU_FIRMWARE.md), где найден первый
незашифрованный образ MCU пульта и расшифрована `06:72`. Здесь разобраны **все**
команды, зарегистрированные в этом MCU, и добавлено кросс-подтверждение с
RC Pro 2.

Границы результата задаются честно: имена в этой прошивке есть только у двух
команд, поэтому остальные описаны структурной сигнатурой (что читают, чем
отвечают, какие подпрограммы вызывают), а не догадками о назначении.

Ни одна команда на реальное устройство не отправлялась.

## Корпус

| Образ | Размер | SHA-256 | База | Строк |
|---|---:|---|---|---:|
| `rc331_0600` (RC2) | 108 136 | `f5ee13337efe61a8e60801a0e21275745a9bcb44277ef45617421471f836beea` | `0x08005000` | 298 |
| `rc520_0600` (RC Pro 2) | 211 920 | распакован из `V01.00.0700_rc520` | `0x08020000` | 774 |

Оба модуля имеют `type=MCU` и **пустой `enc_key`**. `rc520_0600` идентичен во
всех четырёх локальных OTA RC Pro 2 (`V01.00.0400`…`V01.00.0700`): версия
модуля везде `v10.02.01.21_20250825`.

## Что такое шесть каналов

RC2 логирует только номера каналов (`ch0…ch5`), а RC Pro 2 печатает их
расшифровку:

```text
WARNING:A:%d E:%d T:%d R:%d WH1:%d WH2:%d c1:%d c2:%d fo:%d pho:%d rec:%d
        f_m:%d c3:%d rc_m:%d pau:%d wheelmode %d
```

То есть `ch0…ch5` = **A** (aileron), **E** (elevator), **T** (throttle),
**R** (rudder), **WH1**, **WH2** — четыре оси двух стиков плюс два колеса.
Остальные поля строки — кнопки и режимы (`c1`, `c2`, `c3`, фото, запись,
flight mode, RC mode, пауза, режим колеса). Рядом лежат
`drv_rc_stick_init`, `dji_joystick_init`, `rcstick_push_init`.

Это закрывает вопрос, к чему относятся `ch0…ch5` в `06:72`/`06:74`:
к органам управления пульта, а не к радиотракту.

## Кросс-подтверждение на RC Pro 2

В `rc520_0600` та же пара команд присутствует со своими строками
(`get stick value lock: ch0%d … ch5%d`). Handler по `0x08032330`:

```asm
push {r4,r5,r6,lr}
bl   0x8038bd4        ; -> r0 = указатель на состояние stick-lock
ldr  r1, [r0]         ; 4 байта  -> буфер
ldrh r1, [r0, #4]     ; +2 байта -> буфер
ldrb r1,[r0,#2] … ldrb r2,[r0]   ; шесть байт в лог
blx  <printf>
ldrb r0, [r5, #7]
cbz  r0, out
movs r2, #7           ; длина ответа = 7 байт
add  r1, sp, #0x10
bl   0x803c630        ; отправка ответа
```

Ответ ровно **7 байт** — шесть каналов плюс седьмой байт. Это независимо
подтверждает формат payload, восстановленный на RC2.

## Полная таблица команд RC2 MCU

с их структурными сигнатурами: `insns` — длина тела handler'а до возврата,
`payload` — вызывает ли он получение указателя на payload, `ack` — отправляет
ли ответ, `cmp` — с какими константами сравнивает.

## Что удалось и что нет

| Вопрос | Результат |
|---|---|
| Полный список команд MCU | `CONFIRMED`: 21 команда `cmd_set=0x06` (две с нулевым handler) и 4 команды `cmd_set=0x00` |
| `06:72` / `06:74` | `CONFIRMED` по имени, формату payload и длине ответа; подтверждено на двух поколениях пультов |
| Смысл `ch0…ch5` | `CONFIRMED`: A / E / T / R / WH1 / WH2 (по строке RC Pro 2) |
| Имена остальных 19 команд | **Не восстановлены**: прошивка их не логирует. Обход вызовов на глубину 4 не нашёл ни одной строки |
| Внешние имена | 9 из 21 команды `0x06` совпадают с выемкой из `dji_test_userlibs.dll`; это имена уровня DJI Test Platform, а не самой прошивки |
| Таблица команд в `rc520_0600` | **Не найдена** в 12-байтном формате ни при одной базе из перебора; диспетчер у этого поколения устроен иначе |
| Эффект `06:72` на поведение пульта | `UNKNOWN`: требует live-теста с наблюдением `06:74` readback |

Отдельно стоит отметить два handler'а, которые **не отправляют ответ** —
`06:77`, `06:A2`, `06:AC` и весь набор `00:xx`. Для FreeFCC это означает, что
отсутствие ACK на такие кадры не является признаком ошибки.

## Инструменты

Одноразовые скрипты (в `scratchpad`, вне репозитория):

| Скрипт | Назначение |
|---|---|
| `mcu_table.py` | поиск таблицы команд и подбор базы загрузки по границам функций |
| `mcu_handler_strings.py` | строки, на которые ссылается сам handler |
| `mcu_deep.py` | рекурсивный обход вызовов (глубина настраивается) с поиском строк |
| `mcu_globals.py` | атрибуция «немых» handler'ов через общие RAM-глобалы |
| `mcu_sig.py` | структурные сигнатуры: helper'ы, уникальные подпрограммы, сравнения |
| `disasm_thumb.py` | дизассемблирование диапазона (база через `MCU_BASE`) |

Все используют capstone; распаковка модулей — `dji_imah_fwsig.py -f -u` из
`dji-firmware-tools` с `pycryptodome` в отдельном venv.

## Дальнейшие шаги

1. Найти диспетчер `rc520_0600` — там 774 строки против 298, поэтому имена
   остальных команд, скорее всего, восстановимы именно на этом образе.
2. Прогнать тот же разбор на `rc520_1302` (три hw-варианта, 69 768 байт).
3. Live-тест `06:72` на `rc331`: `ch5=1`/`ch5f=0xff`, затем `06:74` readback.
