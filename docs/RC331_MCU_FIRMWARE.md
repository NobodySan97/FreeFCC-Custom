# RC2 (`rc331`) MCU-прошивка: незашифрованный образ и семантика `06:72`

Дата анализа: 2026-07-24.

Этот документ фиксирует первый в корпусе **незашифрованный** образ MCU того
самого пульта, на котором FreeFCC проверяется вживую, и закрывает вопрос по
команде `06:72` — последней opaque-команде legacy-keepalive, которая уходила в
получателя `rc:0` (внешний RC MCU за UART `/dev/ttyHS2`) и до сих пор не имела
доказанной семантики.

Главный результат:

> **`06:72` = `set stick value lock`, `06:74` = `get stick value lock`.**
> Это управление блокировкой значений каналов органов управления пульта, а не
> радио-регион. Историческая подпись «RADIO set region to FCC (01)» /
> «RADIO commit region change» **опровергнута** кодом прошивки.

Ни одна команда на реальное устройство в рамках этого анализа не отправлялась.

## Образ и база загрузки

`ARM Cortex-M firmware, initial SP at 0x20002300, reset at 0x080054ac`,
108 136 байт, единственная таблица векторов в начале файла.

**База загрузки — `0x08005000`, а не `0x08000000`.** Она восстановлена по
критерию «цель ссылки попадает на границу функции»: при `0x08005000` 21 из 25
указателей таблицы команд начинаются прологом или следуют сразу за возвратом
(84%), тогда как ближайшие альтернативы дают ≤16%. Первые 20 КБ флеша занимает
не входящий в модуль bootloader. Это существенно: при неверной базе
дизассемблируется чужой код, и ранняя интерпретация ветки `06:72` получается
ложной.

### Почему это действительно DUML-команды

Независимая перекрёстная проверка: статическая выемка из
`dji_test_userlibs.dll` (проект `какаято_программа`, 144 уникальные команды из
464 send-callsites) даёт для command set `0x06` набор
`01`, `03`, `2F`, `38`, `56`, `79`, `7B`, `80`, `A4`, `A5`, `F5`. Девять из них
(`01`, `03`, `2F`, `38`, `56`, `7B`, `A4`, `A5`, `F5`) присутствуют в таблице.
Совпадение девяти произвольных однобайтовых ID между двумя независимыми
источниками случайным быть не может.

## `06:72` — `set stick value lock`

Handler `0x08011d94` (Thumb):

```asm
push.w {r4,r5,r6,r7,r8,lr}
sub    sp, #0x28
mov    r8, r0            ; сообщение
mov    r5, r1            ; полная длина кадра
bl     0x80185e2         ; r6 = указатель на payload
bl     0x8014ee8         ; r4 = глобальная структура stick-lock
bl     0x80185e6         ; -> sp+0x20 = id, sp+0x24 = index
ldr    r0, [r6]          ; payload[0..3]
str    r0, [r4]          ;   -> ch0..ch3
ldrh   r0, [r6, #4]      ; payload[4..5]
strh   r0, [r4, #4]      ;   -> ch4, ch5
subs   r5, #0xd          ; payload_len = frame_len - 13
uxth   r5, r5
ldrb   r0, [r4, #5]
strb   r0, [r7]          ; ch5      -> 0x2000241c
cmp    r5, #7
blo    skip
ldrb   r0, [r6, #6]      ; payload[6]
strb   r0, [r7, #1]      ; ch5f     -> 0x2000241d
skip:
bl     0x8016f50         ; лог:
       ; " set stick value lock: ch0%d ch1%d ch2%d ch3%d ch4%d ch5%d,
       ;   ch5f:%d, id%d, index%d, len:%d"
bl     0x8018a70         ; ACK
```

Отсюда следует формат payload — шесть однобайтовых каналов и необязательный
седьмой байт:

```text
payload[0] = ch0   payload[3] = ch3
payload[1] = ch1   payload[4] = ch4
payload[2] = ch2   payload[5] = ch5
payload[6] = ch5f  (читается только при payload_len >= 7)
```

Строка-близнец у `06:74` (`0x080117b0`):
`get stick value lock: ch0%d ch1%d ch2%d ch3%d ch4%d ch5%d, id%d, index%d` —
то есть пара set/get над одним и тем же состоянием. Рядом в `.rodata` лежат
`rc_key_report_to_app ch_0 %d ch_1 %d …` и
`c1:%d c2:%d fo:%d pho:%d rec:%d f_m:%d c3:%d rc_m:%d pau:%d wheelmode %d` —
контекст органов управления пульта, а не радиотракта.

### Разбор кадров FreeFCC

Legacy-keepalive отправлял два кадра `06:72` подряд:

| Кадр | ch0 | ch1 | ch2 | ch3 | ch4 | ch5 | ch5f |
|---|---|---|---|---|---|---|---|
| `00 00 00 00 00 01 00` | 0 | 0 | 0 | 0 | 0 | 1 | `0x00` |
| `00 00 00 00 00 01 ff` | 0 | 0 | 0 | 0 | 0 | 1 | `0xff` |

Оба кадра одинаковы во всём, кроме последнего байта `ch5f`: `0x00` → `0xff`.
Payload ровно 7 байт, то есть седьмой байт читается (порог `payload_len >= 7`
выполняется).

| Утверждение | Уровень |
|---|---|
| `06:72` называется `set stick value lock` в самой прошивке | `CONFIRMED` |
| Payload — шесть однобайтовых каналов + опциональный `ch5f` | `CONFIRMED` |
| Два keepalive-кадра различаются только `ch5f` (`00` → `ff`) | `CONFIRMED` |
| Команда относится к радио-региону/FCC | **Опровергнуто** |
| Точное действие `ch5=1` и значений `ch5f` на поведение пульта | `UNKNOWN`; жалобы на блокировку колеса согласуются с `WH2`, но не являются заменой readback |

Практический вывод для FreeFCC: два исторических `06:72` трогали
блокировку значения канала органов управления, а не регион. Начиная с 1.5.48
рантайм эти кадры не отправляет вовсе.

## Что это меняет в общей картине

| Команда | Было | Стало |
|---|---|---|
| `06:72` | route до RC MCU доказан, образа MCU нет, semantics `UNKNOWN` | образ найден и распакован; имя и формат payload восстановлены из кода; «region set/commit» опровергнуто |
| `06:74` | не рассматривалась | `get stick value lock`, парная readback-команда |
| Корпус | незашифрованных MCU-образов не было | `rc331_0600` (RC2) и `rc520_0600` (RC Pro 2, 211 920 байт) — оба plaintext |

`06:8C` не затрагивается: его получатель — `vt_air:0` (air transmission MCU),
в этом образе его нет.

## RC Pro 2: `rc520_0600`

Модуль `rc520_0600_v10.02.01.21_20250825` из OTA `V01.00.0700_rc520` тоже
распаковывается без ключа шифрования: `ARM Cortex-M firmware, initial SP at
0x20019800, reset at 0x08020740`, 211 920 байт. Таблица команд в нём тем же
12-байтным форматом не находится ни при одной базе из перебора
`0x08000000…0x08040000` — структура диспетчера у этого поколения другая и
требует отдельного разбора. Тот же OTA содержит `rc520_1302` (69 768 байт,
три hw-варианта), который не является ELF/Cortex-M образом.

## Дальнейшие шаги

1. Разобрать оставшиеся ветки `06:xx` в `rc331_0600` — прямых строк у них нет,
   поэтому нужен разбор через вызываемые ими глобальные структуры.
2. Найти формат диспетчера в `rc520_0600` и сопоставить наборы команд двух
   поколений.
3. Только с предварительного согласия владельца устройства выполнить
   контролируемую live-проверку `06:72` на `rc331` с немедленным `06:74`
   readback и заранее подготовленным восстановлением исходного состояния.
   Для FreeFCC такая отправка не нужна: команда удаляется как не относящаяся
   к FCC и потенциально затрагивающая колесо.

## Воспроизведение

Скрипты одноразовые, лежат вне репозитория (`scratchpad`): `mcu_table.py`
(поиск таблицы и подбор базы), `mcu_handler_strings.py` (строки handler'ов),
`disasm_thumb.py`, `scan_mcu.py`. Все используют capstone; чтение ELF-секций —
через `readelf -SW`.
