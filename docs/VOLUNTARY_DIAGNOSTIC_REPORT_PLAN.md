# Добровольная отправка диагностического отчёта

## Статус

Идея зафиксирована для будущей реализации. Сейчас кнопки отправки нет,
диагностические данные автоматически не собираются и серверный endpoint не
развёрнут.

Этот механизм предлагается как приоритетная альтернатива автоматической
статистике использования: отчёт создаётся и отправляется только после явного
действия пользователя.

## Цель

Если FCC, Auto FCC, 4G, LED, GPS, обновление или подключение не сработало,
пользователь сможет нажать **Send diagnostic report**, посмотреть состав
отчёта, при желании добавить комментарий и добровольно отправить его
разработчику.

Полезен не максимально большой дамп, а небольшой отчёт, который отвечает на
четыре вопроса:

1. На каком пульте, прошивке и версии приложения возникла проблема?
2. Какая операция выполнялась и с какими настройками?
3. На каком этапе она завершилась или остановилась?
4. Какие подтверждённые результаты были получены до ошибки?

## Предлагаемый текст в приложении

> Если функция не сработала, вы можете добровольно отправить диагностический
> отчёт, чтобы помочь исправить проблему. Перед отправкой вы увидите все
> включённые данные. Серийные номера, координаты, общий журнал Android и
> содержимое DUML-команд не отправляются.

Для текущего англоязычного интерфейса:

> If a feature does not work, you can voluntarily send a diagnostic report to
> help us fix the problem. You can review everything included before sending.
> Serial numbers, location, the full Android log, and DUML command contents are
> never included.

Кнопка должна называться сначала **Review diagnostic report**, а окончательная
отправка выполняться отдельной кнопкой **Send report** на экране просмотра.

## Сценарий пользователя

1. Пользователь воспроизводит проблему.
2. Открывает Log или Info и нажимает **Review diagnostic report**.
3. Выбирает, что не сработало:
   - Connect;
   - Manual FCC;
   - Auto FCC — Home Point;
   - Auto FCC — country check;
   - 4G;
   - LED;
   - GPS;
   - update/download;
   - launch DJI Fly;
   - другое.
4. При желании пишет короткий комментарий: что ожидал и что произошло.
5. Просматривает точный состав отчёта.
6. Нажимает **Send report** либо сохраняет отчёт в файл без отправки.
7. После успешной отправки получает короткий `report_id`, который можно
   сообщить разработчику.

Никакой отправки при старте, ошибке или падении без подтверждения пользователя
не выполняется.

## Какие данные действительно помогут

### 1. Версии и среда

- версия и `versionCode` SkylabFCCfree;
- код модели пульта из `Build.DEVICE`;
- `Build.MODEL`;
- версия Android и API level;
- firmware/build fingerprint пульта без аппаратных идентификаторов;
- код модели дрона, если он уже был штатно определён;
- язык интерфейса и часовой пояс;
- время создания отчёта и время работы процесса.

Эти поля позволяют отличить несовместимость конкретной прошивки от общей
ошибки приложения. Полный factory S/N для этого не нужен.

### 2. Выбранный пользователем контекст проблемы

- категория неисправной функции;
- необязательный комментарий пользователя;
- выбранный Auto FCC mode: `home_point_text`, `periodic_5s` или `off`;
- была ли включена Accessibility-служба;
- разрешены ли уведомления;
- снято ли ограничение батареи для приложения;
- был ли запущен foreground service.

Комментарий ограничивается разумной длиной, например 2 KiB, и показывается в
предпросмотре без изменений.

### 3. Снимок состояния приложения

Следует переиспользовать уже существующие диагностические поля, исключив
приватные значения:

- `status`, `connected`, `hardware_busy`;
- `controller_duml_port`;
- `keepalive_status`, `keepalive_requested`;
- наличие активного Home Point monitor и его последняя причина остановки;
- `fcc_last_attempt_origin`;
- `fcc_last_attempt_outcome`;
- `fcc_last_attempt_port`;
- `fcc_last_attempt_expected_writes`;
- `fcc_last_attempt_flushed_writes`;
- `fcc_last_attempt_matching_acks`;
- длительность последней попытки;
- был ли обнаружен Home Point, но без координат и текста DJI Fly;
- LED/GPS state и безопасный однобайтовый readback;
- состояние 4G-операции: endpoint reachable, количество ожидаемых и реально
  отправленных кадров, стадия ошибки;
- состояние обновления: проверка, загрузка, HTTP status и стадия ошибки.

Важно сохранять семантику: успешная запись FCC-профиля — это подтверждение
записи в транспорт, а не физический readback RF-режима.

### 4. Обезличенный журнал SkylabFCCfree

В отчёт полезно включать последние 200 строк внутреннего журнала приложения,
уже хранящиеся в process-local ring buffer. Перед показом пользователю и
отправкой выполняется обязательная очистка:

- полные DJI serial заменяются на `<redacted-serial>`;
- похожие на Android ID, IMEI, MAC и UUID значения удаляются;
- IP-адреса заменяются на `<redacted-ip>`, кроме номера localhost DUML-порта;
- Home Point, координаты и текст Accessibility-событий удаляются;
- абсолютные пути сокращаются до безопасного имени файла;
- query-параметры URL и токены удаляются.

Если строку нельзя уверенно очистить, её безопаснее исключить целиком.

### 5. Структурированная ошибка

Для последнего сбоя полезно сохранить:

- стабильный внутренний `error_code`;
- этап: `connect`, `write`, `read`, `parse`, `verify`, `download` и т. п.;
- класс исключения;
- очищенное сообщение;
- stack trace только из пакета `com.freefcc.app`, с ограничением длины;
- elapsed time операции;
- число попыток;
- тип завершения чтения: timeout, EOF, I/O error или лимит размера.

Стабильные коды важнее свободного текста: по ним на сервере можно группировать
одинаковые проблемы.

### 6. Минимальное состояние сети

Для сетевых ошибок достаточно:

- сеть доступна: да/нет;
- transport: Wi-Fi, Ethernet, cellular или unknown;
- прошла ли DNS/HTTPS-проверка endpoint;
- HTTP status либо короткий локальный error code.

Не нужны SSID, BSSID, локальный/внешний IP, gateway, DNS-адреса и полный список
интерфейсов.

## Что нельзя включать автоматически

- серийный номер пульта, дрона, батареи или модема;
- Android ID, IMEI, MAC-адрес и рекламные идентификаторы;
- координаты, Home Point, высоту, маршрут и историю полёта;
- текст, прочитанный Accessibility-службой из DJI Fly;
- сырой DUML request/response, wire capture или hex payload;
- полный системный `logcat`;
- журналы других приложений;
- SSID/BSSID, IP-адреса и конфигурацию сети;
- список установленных приложений;
- содержимое пользовательских файлов;
- токены, пароли, URL query parameters и HTTP-заголовки авторизации.

Особенно важно не копировать напрямую существующий LAN `/api/status`: сейчас
он содержит `aircraft_serial` и свободный `device_info`. Для отчёта нужен
отдельный безопасный DTO с allowlist полей, а не blacklist поверх общего JSON.

## Дополнительный расширенный отчёт

Узкий OpenFCC/DJI `logcat` иногда полезен при сложной аппаратной ошибке, но даже
он может содержать serial, текст DJI Fly или другие данные. Поэтому его нельзя
включать в обычный отчёт.

Если позже понадобится расширенный режим, он должен:

- включаться отдельным выключенным по умолчанию флажком;
- собирать только короткое ограниченное окно после явного старта;
- фильтровать строки до сохранения;
- иметь отдельный предпросмотр;
- никогда не добавлять общий Android `logcat`.

Сырые DUML captures должны оставаться ручным лабораторным артефактом и не
входить даже в расширенный пользовательский отчёт.

## Формат отчёта

Для первой версии достаточно одного ограниченного JSON до 64 KiB:

```json
{
  "schema_version": 1,
  "report_id": "client-generated-random-uuid",
  "created_at": "2026-07-26T12:00:00Z",
  "problem_area": "auto_fcc_home_point",
  "user_comment": "Home Point appeared, but FCC was not applied",
  "app": {
    "version": "1.5.x",
    "version_code": 1
  },
  "device": {
    "controller_model": "rc331",
    "aircraft_model": "WA530",
    "android_api": 32
  },
  "configuration": {
    "auto_fcc_mode": "home_point_text",
    "accessibility_enabled": true
  },
  "runtime": {
    "connected": true,
    "controller_port": 40007,
    "keepalive_status": "failed",
    "last_attempt_outcome": "pre_write_connect_failed",
    "expected_writes": 4,
    "flushed_writes": 0,
    "matching_acks": 0
  },
  "error": {
    "code": "home_point_stream_disconnected",
    "stage": "read"
  },
  "logs": [
    "[12:00:01] Auto FCC started",
    "[12:00:06] Stream disconnected"
  ]
}
```

Пример показывает структуру, а не фиксирует вымышленные значения
`versionCode` или конкретное число FCC-кадров.

## Серверная часть

Предлагаемый endpoint:

`POST /api/v1/diagnostics/report`

Требования:

- отдельный непривилегированный сервис на существующем VPS;
- HTTPS;
- строгая JSON schema и allowlist полей;
- максимальный размер 64 KiB;
- rate limit;
- уникальный `report_id` для дедупликации;
- IP не сохраняется в базе, access log endpoint отключён или анонимизирован;
- отчёт хранится ограниченный срок, например 90 дней;
- доступ к отчётам только у администратора;
- агрегирование по `error_code`, app version, controller/aircraft model и
  firmware build;
- сервер отвечает новым коротким support code.

Статический API key внутри APK не обеспечивает реальную защиту. Для публичного
endpoint важнее строгий формат, лимиты, дедупликация и отсутствие опасного
рендеринга пользовательского текста.

## Локальная безопасность

- отчёт формируется заново в момент открытия предпросмотра;
- экран показывает JSON и очищенный журнал полностью;
- отправляется ровно показанная пользователю версия;
- после успешной отправки временный файл удаляется;
- при отмене временный файл также удаляется;
- отчёт можно сохранить локально или отправить через Android Share Sheet
  вместо загрузки на сервер;
- недоступность сервера никак не влияет на функции SkylabFCCfree.

## Изменения, необходимые при реализации

- ввести отдельный allowlisted `DiagnosticReport` DTO;
- добавить стабильные operation/error codes;
- сохранять последний operation result и очищенную ошибку;
- реализовать детерминированный redactor с unit-тестами;
- добавить экран выбора проблемы, комментария и предпросмотра;
- добавить добровольную отправку и локальный export/share;
- развернуть endpoint и закрытое представление отчётов;
- обновить `README.md`, `CHANGELOG.md` и privacy-текст;
- проверить реальным отчётом, что serial, IP, координаты, DJI Fly text, raw
  DUML и общий `logcat` отсутствуют.

## Критерии готовности будущей реализации

- без нажатия пользователя сетевых запросов диагностики нет;
- окончательная отправка требует отдельного подтверждения после предпросмотра;
- сервер получает ровно показанный JSON;
- отчёт содержит достаточно данных, чтобы определить функцию, этап и outcome;
- одинаковые ошибки группируются по стабильному `error_code`;
- serial, идентификаторы, IP, координаты, DJI Fly text, raw DUML и чужой
  `logcat` отсутствуют;
- пользователь получает `report_id`;
- ошибка отправки не влияет на работу приложения;
- после отправки или отмены временный отчёт удаляется.
