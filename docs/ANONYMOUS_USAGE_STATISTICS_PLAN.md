# Анонимная статистика использования

## Статус

Идея зафиксирована для будущего обсуждения и отложена. Сейчас приложение ничего
из описанного ниже не отправляет, серверный endpoint не развёрнут. Приоритетной
альтернативой считается добровольная отправка диагностического отчёта только
по кнопке пользователя: [план диагностического отчёта](VOLUNTARY_DIAGNOSTIC_REPORT_PLAN.md).

## Цель

Собирать минимальную агрегированную статистику, которая поможет понять:

- на каких моделях пультов и дронов используют SkylabFCCfree;
- какой режим FCC выбирают пользователи;
- сколько установок продолжает запускаться после обновлений.

Телеметрия не должна создавать постоянное соединение, опрашивать оборудование
ради статистики или заметно расходовать сеть, процессор и батарею.

## Предлагаемый текст в приложении

> SkylabFCCfree отправляет анонимную статистику использования для улучшения
> приложения: версию приложения, модель пульта и дрона, а также выбранный режим.
> Серийные номера, координаты, журналы и содержимое команд не отправляются.

Для текущего англоязычного интерфейса:

> SkylabFCCfree sends anonymous usage statistics to help improve the app:
> app version, controller and aircraft models, and the selected mode. Serial
> numbers, location, logs, and command contents are never sent.

Предполагаемое поведение: статистика включена по умолчанию, но в приложении
есть понятный переключатель, позволяющий полностью отключить отправку.

## Какие данные разрешено отправлять

### Профиль установки

Отправляется после первого успешного определения оборудования:

- случайный `installation_id`, созданный приложением при установке;
- версия приложения;
- код модели пульта, например `rc331` или `rc520`;
- код модели дрона, например `WA530`;
- версия формата события.

`installation_id` не должен основываться на Android ID, серийном номере,
MAC-адресе или другом аппаратном идентификаторе. После переустановки приложения
создаётся новый случайный идентификатор.

Профиль повторно отправляется только при изменении связки пульт/дрон или пока
сервер ещё не подтвердил первую отправку. Для сравнения локально хранится хеш
уже подтверждённого профиля.

### Check-in при включении

На `BOOT_COMPLETED` создаётся не более одного короткого события:

- `installation_id`;
- версия приложения;
- выбранный режим:
  - `home_point_text`;
  - `periodic_5s`;
  - `off`;
- локальный последовательный номер включения для дедупликации;
- версия формата события.

Если потребуется учитывать ручной FCC, приложение может запоминать последний
фактически использованный режим локально и добавлять его в следующий check-in.
Нажатие кнопки само по себе не должно вызывать сетевой запрос.

## Что запрещено отправлять

- серийный номер пульта, дрона, батареи или модема;
- Android ID, IMEI, MAC-адрес и рекламные идентификаторы;
- координаты, Home Point и маршрут;
- содержимое DUML-кадров;
- журналы приложения, DJI Fly или Android;
- имена Wi-Fi-сетей и сетевые настройки;
- пользовательские файлы и сведения о других приложениях.

IP-адрес неизбежно виден серверу во время HTTPS-запроса, но не должен
сохраняться в базе. Для telemetry endpoint следует отключить access log либо
анонимизировать адрес на уровне reverse proxy.

## Правила отправки

1. Никакого постоянного соединения, фонового polling или таймера.
2. Приложение использует уже известные модели и не выполняет дополнительный
   DUML-опрос ради статистики.
3. Одно отложенное задание ждёт доступной сети, отправляет один HTTPS `POST` и
   завершается.
4. Повторный системный broadcast или перезапуск процесса не должен создавать
   дубликат события для того же включения.
5. Ошибка телеметрии никак не влияет на FCC, Auto FCC, запуск DJI Fly и другие
   функции приложения.
6. При выключенном переключателе задания не создаются, а уже ожидающие задания
   отменяются.

Ожидаемый объём одного запроса — несколько сотен байт.

## Черновой API

### Профиль оборудования

`POST /api/v1/telemetry/device-profile`

```json
{
  "schema_version": 1,
  "installation_id": "random-uuid",
  "app_version": "1.5.x",
  "controller_model": "rc331",
  "aircraft_model": "WA530"
}
```

### Включение

`POST /api/v1/telemetry/boot-checkin`

```json
{
  "schema_version": 1,
  "installation_id": "random-uuid",
  "app_version": "1.5.x",
  "boot_sequence": 42,
  "selected_mode": "home_point_text"
}
```

Ответ на успешную запись:

```json
{
  "ok": true
}
```

## Серверная часть

Предлагается разместить небольшой отдельный сервис на существующем VPN/VPS,
не связывая его с процессами VPN:

- HTTPS endpoint за reverse proxy;
- отдельный непривилегированный systemd unit;
- SQLite для первоначального объёма данных;
- строгая проверка JSON и ограничение размера запроса;
- rate limit;
- уникальные ключи для защиты от дублей;
- отсутствие IP-адресов и сырых HTTP-заголовков в базе;
- только агрегированные отчёты по версиям, моделям и режимам.

Статический секрет внутри APK не следует считать защитой: его можно извлечь.
Основная защита публичного endpoint — валидация, дедупликация, ограничение
размера и частоты запросов.

## Изменения, необходимые при реализации

- добавить клиент телеметрии и локальное состояние отправок;
- привязать check-in к существующему обработчику `BOOT_COMPLETED`;
- запускать синхронизацию профиля после штатного определения модели дрона;
- добавить текст и переключатель в раздел информации;
- добавить тесты дедупликации, выключения и формирования безопасного payload;
- обновить `README.md` и `CHANGELOG.md`, убрав утверждения об отсутствии
  tracking/backend и точно перечислив отправляемые поля;
- развернуть endpoint и проверить реальные записи, дедупликацию и отсутствие
  запрещённых данных.

## Критерии готовности будущей реализации

- одна установка создаёт не более одного `boot-checkin` на включение;
- неизменный профиль оборудования не отправляется повторно;
- смена дрона обновляет профиль без передачи его серийного номера;
- выключенная статистика не создаёт сетевых запросов;
- недоступность сервера не влияет на основные функции приложения;
- база и proxy logs не содержат IP, серийников, координат, логов или DUML;
- публичное описание приложения соответствует фактическому поведению.
